# ADR 0001 — Choix de l'UI

- **Statut** : Proposé — décision à la fin de la semaine 3
- **Date** : 2026-10-21
- **Décideurs** : maintainer plstudio
- **Portée** : `pls-ui`, expérience éditeur, tests UI, packaging

## Contexte

plstudio doit offrir un éditeur de code rapide et un IDE complet, en Rust, tout en restant réversible sur le choix de l'UI. Trois candidats sont crédibles :

1. **egui + éditeur maison** : 100 % Rust, léger, mais la couche texte (IME, sélection, multi-curseur, undo, BiDi, accessibilité) est à écrire.
2. **GPUI** : moteur de rendu de Zed, rapide. La crate `gpui` peut être sous Apache-2.0, mais l'éditeur de Zed reste GPL-3.0 ; un fork de l'éditeur est incompatible avec MIT/Apache.
3. **Webview + Monaco/CodeMirror** : éditeur mature (IME, BiDi, accessibilité), mais ajoute une pile web, de la RAM et du temps de démarrage ; le moteur reste Rust.

Le choix ne doit pas être fait avant d'avoir mesuré. Le moteur est indépendant de l'UI, donc la décision reste réversible.

## Décision

- Organiser un **spike de 5 jours** en semaine 1-3.
- Évaluer les trois candidats avec la même application de test : 5 000 lignes, 50 000 lignes, IME français, sélection, multi-curseur, undo, recherche, coloration, diagnostics LSP.
- Mesurer : fps au scroll, latence de frappe, RAM, temps de démarrage, temps de mise en œuvre.
- **Date limite : fin S3.** ADR 0001 signé, aucune prolongation.
- **Défaut** : egui si aucun candidat ne se détache clairement.
- `pls-ui` isole le choix ; `pls-engine` ne dépend d'aucune UI.
- L'arabe/BiDi est un signal pour la v2, pas un critère éliminatoire de la v0.1.

## Critères

| Critère | Poids | Éliminatoire |
|---|---|---|
| IME français (accents, composition) | Fort | Oui |
| 60 fps sur 5 000 lignes | Fort | Oui |
| Latence de frappe < 16 ms | Fort | Oui |
| RAM au repos | Moyen | Non |
| Coût estimé en semaines | Fort | Non |
| Licence compatible MIT/Apache | Fort | Oui |
| Accessibilité clavier | Moyen | Non |
| RTL/BiDi v2 | Faible (v0.1) | Non |
| Testabilité (snapshots, CI) | Moyen | Non |
| Packaging et taille binaire | Moyen | Non |

## Conséquences

### Si egui

- 100 % Rust, démarrage rapide, binaire compact.
- Écrire la couche texte : sélection, multi-curseur, undo, IME, layout.
- BiDi et accessibilité limités ; à traiter en v2.
- Tests UI via `egui_kittest`.

### Si GPUI

- Vérifier la licence de la crate `gpui` (Apache-2.0 ?) et ne pas réutiliser l'éditeur Zed (GPL-3.0).
- Courbe d'apprentissage et intégration à évaluer.
- Écosystème plus jeune ; risque de maintenance.

### Si webview + Monaco/CodeMirror

- Éditeur mature immédiatement : IME, BiDi, accessibilité, multi-curseur.
- Ajoute Node/JS au build, une webview, de la RAM et du temps de démarrage.
- Tests UI via Playwright ; snapshots différents.
- Le moteur Rust reste inchangé ; `pls-ui` devient une coquille native + webview.

## Alternatives écartées

- **Fork de Zed** : GPL-3.0, incompatible avec MIT/Apache.
- **Éditeur existant en C/C++** : intégration et licence à vérifier, coût d'intégration élevé.
- **Décider maintenant** : prématuré sans mesures.
